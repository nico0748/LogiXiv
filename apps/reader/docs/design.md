# PaperLens 設計メモ

最終更新: 2026-10-13

## 方針転換

### 1 回目（2026-10）: 全文対訳から読解ノートへ

旧 LogiXiv（論文対訳リーダー）は「1文ごとの対訳を作り、HTML に書き出して共有する OSS」だった。
PaperLens は目的を「論文を読みながら、読解の記録を Markdown に残すアプリ」に変えた。

| 項目 | 旧 LogiXiv | PaperLens（当初） |
| --- | --- | --- |
| 中心にある成果物 | 対訳付き HTML | 読解ノート（note.md） |
| 訳の単位 | GROBID で切った全文 | 利用者が選んだ箇所だけ |
| 保存先 | `~/.logixiv/documents/` | 利用者が選んだフォルダ（保管庫） |
| 補足情報 | 訳とメモ | 訳、用語の説明、TeX の数式、段階ごとの記録 |
| 翻訳の経路 | MCP 経由の Claude | Claude API（キーはブラウザに保存）。手入力も可 |

全文対訳をやめた理由は、読解の記録に必要なのは「自分が引っかかった箇所」だけだからである。
全文を訳すと GROBID の環境構築が必要になり、訳の量が多すぎて記録に残らない。

### 2 回目: 2 つのアプリを 1 つにまとめた

旧 LogiXiv の文分割と対訳を PaperLens に取り込み、製品名を PaperLens に統一した。
全文の対訳は Claude が MCP 経由で入れるので、翻訳 API のキーも追加費用も要らない。
選んだ箇所の訳・用語・数式・記録という PaperLens の使い方はそのまま残した。

| 項目 | 今の PaperLens |
| --- | --- |
| 中心にある成果物 | 読解ノート（note.md）。対訳は論文フォルダの `sentences.json` に並べて置く |
| 訳の単位 | 両方。全文は 1 文ずつ（MCP 経由の Claude）、選んだ箇所は画面から（Claude API か手入力） |
| 保存先 | 利用者が選んだフォルダ（保管庫）。旧 LogiXiv の置き場は使わない |
| 文の区切り | 旧 LogiXiv と同じ（GROBID、無ければ pdf.js の簡易解析）。コードも `packages/core` / `packages/server` を共有する |
| 画面 | Obsidian に似た形（リボン、左右のサイドバー、ステータスバー）。右サイドバーの「対訳」タブが旧 LogiXiv の画面にあたる |

「全文を訳すと記録に残らない」という 1 回目の理由は、対訳を note.md に入れないことで避けた。
対訳は `sentences.json` に置き、ノートには自分の言葉の要点だけを書く。

旧 LogiXiv の単一 HTML への書き出し・取り込みは、まだ移していない。それまでは旧 Web 画面（`apps/web`）を残す。

## アプリの形（SecOwl と同じ構成）

2026-10-12 に、ブラウザ単体（File System Access API）の形から、SecOwl と同じ形に移した。

```
            ┌────────────── 保存先フォルダ（Obsidian の保管庫として開ける） ──────────────┐
            │  _templates/reading-note.md   papers/<id>/{paper.pdf, note.md, paperlens.json, sentences.json} │
            └──────────▲───────────────────────────▲──────────────────────▲──────────┘
                       │ 読み書き＋見張り              │ 読み書き                 │ 読み書き
       ┌───────────────┴─────────┐       ┌─────────┴─────────┐     ┌───────┴──────┐
       │ ローカルサーバー（server/）│       │ MCP サーバー（mcp/） │     │ Obsidian など │
       │ 127.0.0.1 だけで待ち受け  │       │ stdio。アプリ不要   │     └──────────────┘
       └───────▲─────────────────┘       └─────────▲─────────┘
               │ /api と変更の通知（SSE）           │
   ┌───────────┴───────────┐               Claude Desktop / Claude Code
   │ 画面（src/）           │
   │ ブラウザ or Electron   │
   └───────────────────────┘
```

- 論文フォルダの処理（`src/lib/papers.ts`、`template.ts`、`model.ts`）は、画面・サーバー・MCP で同じものを使う。保存先の違いは `Vault`（ブラウザのフォルダ、メモリ、Node.js のファイル）で吸収する。
- サーバーは保存先をフォルダごとに見張り、MCP サーバーや Obsidian の書き込みを画面へ通知する（Server-Sent Events）。自分の画面からの書き込みは、更新時刻で見分けて通知しない。
  Linux の `fs.watch` の recursive は、一時ファイルからの置き換えを2回目以降に取りこぼすため使わない。
- 注釈（マーカー・用語・数式）は丸ごと上書きせず、追加・更新・削除の操作として書き込む。書き込む直前にファイルを読み直して操作を当てるので、画面とエージェントが同時に書いても互いの変更を消さない。画面側は「保存先にあると分かっている状態」との差分を送る。
- 記録欄は `<!-- field -->` の中だけを書き換える。読み直してから書くのは画面でもエージェントでも同じ。
- 保存先は `PAPERLENS_DATA` → 設定ファイル（`PAPERLENS_CONFIG`）→ 初期値の順に決める。MCP の登録方法には設定ファイルの場所を入れるため、画面で保存先を変えるとエージェントも付いてくる。
- サーバーは Host と Origin を確かめ、同じ端末の画面からの操作だけを受け付ける。論文 ID と保存先の外を指すパスは受け付けない。
- `npm run build:single` の単体 HTML は従来どおりブラウザ単体で動く（サーバーが無ければ保管庫を選ぶ画面を出す）。対訳はサーバーがあるときだけ使える。
- 対訳（`sentences.json`）の読み書きは `server/sentences.ts` に集めた。画面の API と MCP サーバーの両方がここを呼ぶ。解析の進み具合は `sentences.status.json` に書き、別プロセスからも「解析中」「失敗した」が見えるようにした。詳しくは [../../../docs/architecture.md](../../../docs/architecture.md) の「全体の形」。

### MCP のツール

画面の操作をすべてツールにした。本文の文字列でマーカーを引けるよう、サーバー側で pdf.js から文字の位置を取り出し、画面と同じ座標（ページに対する割合）で保存する。

| 画面の操作 | ツール |
| --- | --- |
| PDF を追加 | `import_paper`（端末のパスか URL） |
| 論文一覧、論文を開く | `list_papers`、`get_paper`、`get_note`、`read_paper_text`、`find_in_paper` |
| マーカー・訳・メモ | `add_highlight`、`update_highlight`、`remove_annotation` |
| 用語を調べる | `add_term`、`update_term`、`remove_annotation` |
| 数式にする | `add_equation`、`update_equation`、`remove_annotation` |
| 記録タブ、読解の段階 | `set_fields`、`set_status`、`set_meta` |
| テンプレートを編集 | `get_template`、`set_template`、`reset_template` |
| グラフ | `get_graph`、`search_notes` |
| 設定（保存先） | `get_settings`、`set_data_root` |
| 対訳タブ | `get_sentence_outline`、`get_sentences`、`get_translation_batch`、`search_sentences`、`parse_sentences`、`set_translations`、`add_sentence_note`、`update_glossary`、`skip_sentences`、`fix_sentence_boundary` |

対訳のツールは旧 LogiXiv の MCP（`packages/mcp`）の 11 ツールを、論文 ID（`paper`）で使えるように移したもの（`list_documents` は `list_papers` にまとめた）。設計は [../../../docs/mcp.md](../../../docs/mcp.md) にある。

`PAPERLENS_MCP_READONLY=1` で読み取りのツールだけを公開する。

## 画面構成

Obsidian の画面の形にそろえた。

```
┌──┬────────────┬───────────────────────────┬──────────────────────────┐
│論│ 論文一覧    │ [論文の題名]  ← タブの見出し │ 対訳 | 訳 | 用語 | 数式 | 記録 │
│検│ 検索        │                           │                          │
│リ│ （既定は閉） │  PDF。文を選ぶと操作メニュー  │ 1 文ずつの対訳カード        │
│グ│            │  [●●●●] 訳す 用語を調べる    │ 選んだ箇所の訳、用語の説明    │
│  │            │  数式にする                 │ KaTeX の数式、記録欄         │
│設│            │                           │                          │
│？│            │                           │            ステータスバー   │
└──┴────────────┴───────────────────────────┴──────────────────────────┘
```

- リボン（左端）: 論文一覧、検索、リスト、グラフ。下に設定とヘルプ。
- 左サイドバー: 保管庫の論文一覧（読解の段階を表示）と、読解ノートの横断検索。初めて開いたときは閉じている（`⌘/Ctrl + \` で開閉）。PDF を読む幅を優先した。
- 中央: タブの見出しの下に、pdf.js で描画した論文。テキスト層を重ねているので文を選択できる。マーカーは色を4つ用意した。「文の枠」を出すと、対訳の文の位置が PDF に重なる。
- 右サイドバー: 5つのタブ。対訳は 1 文ずつのカード（訳・メモ・訳さない記録・区切りの直し・用語集）。訳・用語・数式は PDF での操作から追加され、記録はテンプレートの入力欄から作る。
- ステータスバー: 保存の状態、対訳の解析方式と訳の進み具合、マーカーの数、論文の数、保管庫の名前。
- リスト（`⌘/Ctrl + Shift + L`）: 広いモーダル。単語帳（各論文の用語と、対訳の用語集）と数式帳を、全論文から集める。項目を選ぶと、その論文の該当ページへ移る。
- グラフ: 論文と用語のつながり。同じ用語を調べた論文は近くに配置される。
- 設定とヘルプはモーダルで開く。設定は Obsidian の設定画面と同じ、左に項目・右に中身の形。
- サイドバーの開閉と幅、開いている論文は `.paperlens/workspace.json` に保存する（Obsidian の `.obsidian/workspace.json` と同じ考え方）。

```
<保管庫>/
  .paperlens/workspace.json     画面の配置
  _templates/reading-note.md    テンプレート（利用者が編集できる）
  papers/20261012-attention/
    paper.pdf                   取り込んだ PDF
    note.md                     読解ノート

```

データベースは使わない。アプリを使わなくなっても、ノートと PDF はそのまま残る。
Obsidian の保管庫にしているフォルダを選べば、Obsidian からも同じノートを開ける。

## テンプレートと読解ノート

テンプレートは普通の Markdown である。アプリが読み書きする範囲を HTML コメントで囲む。
Obsidian の閲覧画面ではコメントが表示されない。

```markdown
## 1. 概要をつかむ

### 一言でいうと
<!-- field: summary | 一言でいうと | 何をして何が分かったかを1〜2文で書く -->
（記録タブで入力した内容がここに入る）
<!-- /field -->

## マーカーと訳
<!-- list: highlights -->
（アプリが書き出す）
<!-- /list -->
```

- `field` は「ID | 見出し | 入力のヒント」の形。直前の `##` 見出しが、記録タブでのまとまりになる。
- `list` はアプリが書き出す一覧。`highlights`、`terms`、`equations` の3種類がある。
- `{{title}}`、`{{date}}`、`{{pdf}}`、`{{id}}` は論文の取り込み時に置き換わる。
- 読解の段階は frontmatter の `status` に入る。

初期のテンプレートは、読む段階を4つに分けた（概要をつかむ、精読する、検討する、まとめる）。
段階ごとに書く項目を決めておくと、途中で読むのをやめても、どこまで理解したかがノートから分かる。

### 書き込みの規則

1. 書き込む直前にノートを読み直し、`field` と `list` の範囲だけを書き換える。範囲の外側は変更しない。
2. 同じノートへの書き込みは順番に処理する。読み直しと書き込みの間に別の更新が入らない。
3. 別のアプリでノートを書き換えた場合、アプリに戻った時点で読み直す。
4. `field` の中身は、Obsidian で直接書き換えてもアプリに反映される（ノートが正）。
5. `list` の中身は `paperlens.json` から毎回作り直す。一覧を直すときはアプリの右側で編集する。

5 は割り切りである。一覧を Markdown から逆に読み取る処理は、書式の揺れに弱いため見送った。

### 書き出す Markdown の形

- マーカー: Obsidian のコールアウト（`> [!quote] p.3（黄）`）。ブロック ID（`^h-...`）を付けるので、他のノートから参照できる。
- 用語: `### [[用語]]` の形。Obsidian のグラフビューでも論文と用語がつながる。
- 数式: `$$ ... $$`。Obsidian と GitHub の両方で表示できる。

## Claude の使い方

| 操作 | 送る内容 | 返す内容 |
| --- | --- | --- |
| 訳す | 選択した文、前後約600字、論文の題名 | 訳文 |
| 用語を調べる | 用語、前後約600字、題名 | 見出し語、読み、定義、説明、この論文での使われ方、関連語 |
| 数式にする | 抽出した文字列、選択範囲の画像、前後の本文 | TeX、記号の説明 |

全文の対訳はこの表に入らない。対訳は Claude が MCP 経由で入れ、画面からは Claude API を呼ばない（読む・直す・区切りを整えることに集中する）。

- 応答は JSON スキーマを指定した構造化出力で受け取る。
- 数式は PDF から抽出した文字列だと記号が崩れるため、選択範囲を切り出した画像も送る。
- API キーはブラウザの localStorage に保存し、保管庫には書かない。保管庫を同期や Git で共有してもキーは含まれない。
- キーが無くても、訳・用語・数式はすべて手で入力できる。
- 日本語の書き方は yomiyasu の方針に合わせ、システムプロンプトで指定した（である調、1文40字前後、比喩を使わない、定訳に英語を添える）。

## デザイン

デジタル庁デザインシステム（DADS）を参考にした。

- 色: 主色は Blue-900、文字は Solid Gray 900、境界線は Solid Gray 200。色の値は近似値で、正式な値は DADS の Figma データで確認する必要がある。
- フォーカス: DADS の規定どおり、黄色（Yellow-300）と黒の2重線にした。
- 文字: Noto Sans JP、本文 16px、行間 1.7。
- ボタン: 角丸 8px。主ボタンは塗り、副ボタンは枠線、補助操作は下線付きの文字。
- マーカー色: 黄・緑に加え、DADS の検索ハイライト色（シアン、マゼンタ）を使った。
- 暗い表示も用意した。DADS には暗い配色の規定が無いため、明るい配色の対比を保つ値を独自に決めた。

## 画面の文言

yomiyasu（AI が書いた日本語の不自然さを直す指針）を参考に、次の規則で書いた。

- 機能の説明は「〜できます」、利用者への依頼は「〜してください」と書き分ける。
- 比喩を使わない。「保存しています」「保存できませんでした」のように状態をそのまま書く。
- 前置きや締めの言葉を書かない。絵文字を使わない。
- ボタンは動作を書く（「PDF を追加」「訳す」「保存する」）。

## 技術構成

- Vite + React + TypeScript
- pdf.js 5.4（描画とテキスト層）
- KaTeX（数式の表示）
- @anthropic-ai/sdk（ブラウザから直接呼ぶ）
- ローカルサーバー: Node.js の http（依存なし）。`vite build -c vite.server.config.ts` で `dist-server/` にまとめる
- MCP サーバー: @modelcontextprotocol/sdk 1.30 と zod 3（旧 LogiXiv の packages/mcp と同じ版）
- 文分割と対訳: `packages/core`（型・TEI パーサ・文分割・正規化ハッシュ・移行）と `packages/server`（GROBID 呼び出し、pdf.js の簡易解析）。GROBID は Docker（`docker/grobid.yml`）
- デスクトップ版: Electron 38、配布物は electron-builder
- File System Access API（単体 HTML のときだけ）。対応ブラウザは Chrome と Edge。
