# PaperLens 設計メモ

最終更新: 2026-10-13

## 方針転換

### 1 回目（2026-10）: 全文対訳から読解ノートへ

旧 LogiXiv（論文対訳リーダー）は「1文ごとの対訳を作り、HTML に書き出して共有する OSS」だった。
PaperLens は目的を「論文を読みながら、読解の記録を Markdown に残すアプリ」に変えた。

| 項目 | 旧 LogiXiv | PaperLens（当初） |
| --- | --- | --- |
| 中心にある成果物 | 対訳付き HTML | 読解ノート（note.md） |
| 訳の単位 | GROBID で切った全文 | 利用者が選んだ箇所だけ |
| 保存先 | `~/.logixiv/documents/` | 利用者が選んだフォルダ（保管庫） |
| 補足情報 | 訳とメモ | 訳、用語の説明、TeX の数式、段階ごとの記録 |
| 翻訳の経路 | MCP 経由の Claude | Claude API（キーはブラウザに保存）。手入力も可 |

全文対訳をやめた理由は、読解の記録に必要なのは「自分が引っかかった箇所」だけだからである。
全文を訳すと GROBID の環境構築が必要になり、訳の量が多すぎて記録に残らない。

### 2 回目: 2 つのアプリを 1 つにまとめた

旧 LogiXiv の文分割と対訳を PaperLens に取り込み、製品名を PaperLens に統一した。
全文の対訳は Claude が MCP 経由で入れるので、翻訳 API のキーも追加費用も要らない。
選んだ箇所の訳・用語・数式・記録という PaperLens の使い方はそのまま残した。

| 項目 | 今の PaperLens |
| --- | --- |
| 中心にある成果物 | 読解ノート（note.md）。対訳は論文フォルダの `sentences.json` に並べて置く |
| 訳の単位 | 両方。全文は 1 文ずつ（MCP 経由の Claude）、選んだ箇所は画面から（Claude API か手入力） |
| 保存先 | 利用者が選んだフォルダ（保管庫）。旧 LogiXiv の置き場は使わない |
| 文の区切り | 旧 LogiXiv と同じ（GROBID、無ければ pdf.js の簡易解析）。コードも `packages/core` / `packages/server` を共有する |
| 画面 | Obsidian に似た形（リボン、左右のサイドバー、ステータスバー）。右サイドバーの「対訳」タブが旧 LogiXiv の画面にあたる |

「全文を訳すと記録に残らない」という 1 回目の理由は、対訳を note.md に入れないことで避けた。
対訳は `sentences.json` に置き、ノートには自分の言葉の要点だけを書く。

旧 LogiXiv の単一 HTML への書き出し・取り込みは、まだ移していない。それまでは旧 Web 画面（`apps/web`）を残す。

## アプリの形（SecOwl と同じ構成）

2026-10-12 に、ブラウザ単体（File System Access API）の形から、SecOwl と同じ形に移した。

```
            ┌────────────── 保存先フォルダ（Obsidian の保管庫として開ける） ──────────────┐
            │  _templates/reading-note.md   papers/<id>/{paper.pdf, note.md, paperlens.json, sentences.json} │
            └──────────▲───────────────────────────▲──────────────────────▲──────────┘
                       │ 読み書き＋見張り              │ 読み書き                 │ 読み書き
       ┌───────────────┴─────────┐       ┌─────────┴─────────┐     ┌───────┴──────┐
       │ ローカルサーバー（server/）│       │ MCP サーバー（mcp/） │     │ Obsidian など │
       │ 127.0.0.1 だけで待ち受け  │       │ stdio。アプリ不要   │     └──────────────┘
       └───────▲─────────────────┘       └─────────▲─────────┘
               │ /api と変更の通知（SSE）           │
   ┌───────────┴───────────┐               Claude Desktop / Claude Code
   │ 画面（src/）           │
   │ ブラウザ or Electron   │
   └───────────────────────┘
```

- 論文フォルダの処理（`src/lib/papers.ts`、`template.ts`、`model.ts`）は、画面・サーバー・MCP で同じものを使う。保存先の違いは `Vault`（ブラウザのフォルダ、メモリ、Node.js のファイル）で吸収する。
- サーバーは保存先をフォルダごとに見張り、MCP サーバーや Obsidian の書き込みを画面へ通知する（Server-Sent Events）。自分の画面からの書き込みは、更新時刻で見分けて通知しない。
  Linux の `fs.watch` の recursive は、一時ファイルからの置き換えを2回目以降に取りこぼすため使わない。
- 注釈（マーカー・用語・数式）は丸ごと上書きせず、追加・更新・削除の操作として書き込む。書き込む直前にファイルを読み直して操作を当てるので、画面とエージェントが同時に書いても互いの変更を消さない。画面側は「保存先にあると分かっている状態」との差分を送る。
- 記録欄は `<!-- field -->` の中だけを書き換える。読み直してから書くのは画面でもエージェントでも同じ。
- 保存先は `PAPERLENS_DATA` → 設定ファイル（`PAPERLENS_CONFIG`）→ 初期値の順に決める。MCP の登録方法には設定ファイルの場所を入れるため、画面で保存先を変えるとエージェントも付いてくる。
- サーバーは Host と Origin を確かめ、同じ端末の画面からの操作だけを受け付ける。論文 ID と保存先の外を指すパスは受け付けない。
- `npm run build:single` の単体 HTML は従来どおりブラウザ単体で動く（サーバーが無ければ保管庫を選ぶ画面を出す）。対訳はサーバーがあるときだけ使える。
- 対訳（`sentences.json`）の読み書きは `server/sentences.ts` に集めた。画面の API と MCP サーバーの両方がここを呼ぶ。解析の進み具合は `sentences.status.json` に書き、別プロセスからも「解析中」「失敗した」が見えるようにした。詳しくは [../../../docs/architecture.md](../../../docs/architecture.md) の「全体の形」。

### MCP のツール

画面の操作をすべてツールにした。本文の文字列でマーカーを引けるよう、サーバー側で pdf.js から文字の位置を取り出し、画面と同じ座標（ページに対する割合）で保存する。

| 画面の操作 | ツール |
| --- | --- |
| 追加（PDF ファイル、URL） | `import_paper`（端末のパス、URL、arXiv の番号） |
| 論文一覧、論文を開く | `list_papers`、`get_paper`、`get_note`、`read_paper_text`、`find_in_paper` |
| マーカー・訳・メモ | `add_highlight`、`update_highlight`、`remove_annotation` |
| 用語を調べる | `add_term`、`update_term`、`remove_annotation` |
| 数式にする | `add_equation`、`update_equation`、`remove_annotation` |
| 記録タブ、読解の段階、書誌情報 | `set_fields`、`set_status`、`set_meta` |
| BibTeX をコピー | `get_bibtex` |
| 論文一覧の検索 | `search_notes` |
| テンプレートを編集 | `get_template`、`set_template`、`reset_template` |
| グラフ | `get_graph`、`search_notes` |
| 設定（保存先） | `get_settings`、`set_data_root` |
| 発表スライドと論文の対応 | `get_slide_markups`、`link_slide_markup`、`unlink_slide_markup`、`set_slide_markup_memo`（スライドを囲むのは画面だけ） |
| 対訳タブ | `get_sentence_outline`、`get_sentences`、`get_translation_batch`、`search_sentences`、`parse_sentences`、`set_translations`、`add_sentence_note`、`update_glossary`、`skip_sentences`、`fix_sentence_boundary` |

対訳のツールは旧 LogiXiv の MCP（`packages/mcp`）の 11 ツールを、論文 ID（`paper`）で使えるように移したもの（`list_documents` は `list_papers` にまとめた）。設計は [../../../docs/mcp.md](../../../docs/mcp.md) にある。

`PAPERLENS_MCP_READONLY=1` で読み取りのツールだけを公開する。

2026-10-13 の変更:

- `set_meta` の `value` は、文字列か文字列の配列を受け付ける。著者など一覧の項目は配列で渡す。複数行の値の項目は書き換えない。
- `get_paper` の `frontmatter` は、一覧を配列で返す（以前は `tags` が `"[paper]"` の文字列で返っていた）。`list_papers` に `authors` と `arxiv` が増えた。
- `search_notes` の当たりに `region`（`frontmatter`、`field`、`list:highlights`、`list:terms`、`list:equations`、`body`）と、記録欄の ID の `field` が付く。HTML コメントの行は当たりに含めない。
- `get_bibtex` を足した（読み取り）。画面の「BibTeX をコピー」と同じ内容を返す。
- `import_paper` は `{ id, note, existing, meta }` を返す。arXiv の論文は題名・著者・年・DOI を frontmatter に入れ、同じ arXiv の論文が既にあれば取り込まずに `existing: true` とその ID を返す。DOI のリンクは専用の文言で断る。

### arXiv からの取り込み

- 入力（abs／pdf の URL、`arXiv:` 付きの番号、番号だけ、旧形式の `hep-th/9901001`）を `server/arxiv.ts` の `normalizeSource` で見分け、版の番号を除いた ID で重複を調べる。arXiv 以外の URL は、リダイレクト後の URL が frontmatter の `url` と同じなら既存とみなす。
- 書誌情報は `export.arxiv.org/api/query` の Atom から取る。取れないとき（429・503 を含む）は書誌情報なしで続ける。PDF の取得が 429・503 のときは、やり直さずに止め、`Retry-After` の秒数を文言に添える。
- arXiv の利用条件（3 秒に 1 回、同時に 1 接続）を守るため、arxiv.org への接続はすべて `arxivQueue` を通し、前の接続が終わってから 3 秒空ける。
  キューはプロセスごとに持つ。ローカルサーバー（画面）と MCP サーバーは別のプロセスなので、同時に取り込むと合わせて 3 秒以内に 2 回接続しうる。
  プロセスをまたぐ排他（保存先のロックファイルなど）は、取り込みが手作業で 1 件ずつ行われる使い方では釣り合わないため、入れていない。
- フォルダ名と `# 見出し` は、URL からの取り込みでは題名（arXiv の題名、PDF の題名、ファイル名の順）から作る。ファイルからの取り込みのフォルダ名は変えていない。

### URL からの取り込みの安全策

`server/fetchpdf.ts` を通す。MCP の `import_paper` に URL を渡したときも同じである。

- http と https だけを許す。利用者名やパスワードを含む URL は断る。
- 接続の前に `dns.lookup(host, { all: true })` で IP を確かめ、ループバック・プライベート・リンクローカル・CGNAT・マルチキャストなど
  （IPv4 の 0/8、10/8、100.64/10、127/8、169.254/16、172.16/12、192.0.0/24、192.168/16、198.18/15、224/3、IPv6 の ::、::1、fc00::/7、fe80::/10、ff00::/8）
  には接続しない。IPv4 を写した IPv6、NAT64（64:ff9b::/96）、6to4（2002::/16）は中の IPv4 で判定する。リダイレクトのたびに確かめ直す。
- 構内だけで公開されている機関リポジトリから取り込むときは、環境変数 `PAPERLENS_ALLOW_PRIVATE_URLS=1` で IP の確認を止められる。設定画面には出さない。
- リダイレクトは 5 回、時間は合計 60 秒、大きさは 200MB まで。最初の 5 バイトが `%PDF-` でなければ読むのを止める。
- `User-Agent: PaperLens/<版> (+https://github.com/nico0748/LogiXiv)` を付ける。Cookie と認証のヘッダーは付けない。
- 端末のパスからの取り込みは MCP だけが使う。大きさは `fs.stat` で確かめる。

残した隙間: 確かめた後に `fetch` が名前をもう一度解決するので、その間に答えを変える手口（DNS rebinding）は防げない。
`node:https` の `request()` に `lookup` を渡せば、依存を足さずに解決結果を固定できる。今回は見送った。
`%PDF` でない応答は保存も返却もせず、エラーの文言には状態の番号しか入れないので、この手口で得られるのは
「内部の機器に GET を 1 回送らせる」ことだけである。
Node.js 22 の `fetch` は `HTTPS_PROXY` を読まないので、プロキシの内側では URL から取り込めない（README の「うまく動かないとき」）。

## 画面構成

Obsidian の画面の形にそろえた。

```
┌──┬────────────┬───────────────────────────┬──────────────────────────┐
│論│ 論文一覧    │ [論文の題名]  ← タブの見出し │ 対訳 | 訳 | 用語 | 数式 | 記録 │
│検│ 検索        │                           │                          │
│リ│ （既定は閉） │  PDF。文を選ぶと操作メニュー  │ 1 文ずつの対訳カード        │
│グ│            │  [●●●●] 訳す 用語を調べる    │ 選んだ箇所の訳、用語の説明    │
│  │            │  数式にする                 │ KaTeX の数式、記録欄         │
│設│            │                           │                          │
│？│            │                           │            ステータスバー   │
└──┴────────────┴───────────────────────────┴──────────────────────────┘
```

- リボン（左端）: 論文一覧、検索、リスト、グラフ。下に設定とヘルプ。設定には保存先、Claude、テンプレート、AI エージェント（MCP）の登録方法を置く。
- 左サイドバー: 保管庫の論文一覧（読解の段階: 未読、概要把握、精読、検討、まとめ済み）と、読解ノートの横断検索。初めて開いたときは閉じている（`⌘/Ctrl + \` で開閉）。PDF を読む幅を優先した。
  一覧の検索欄は題名・著者・年で一覧を絞り、2 文字以上ならノートの中の当たり（記録欄、マーカーと訳、用語、数式、本文）も出す。
  段階のチップで絞り込める（覚えるのは段階だけで、検索の語は覚えない）。開いている論文は、絞り込みの外でも一覧に残す。
- 中央: タブの見出しの下に、pdf.js で描画した論文。テキスト層を重ねているので文を選択できる。マーカーは色を4つ用意した。「文の枠」を出すと、対訳の文の位置が PDF に重なる。
  ツールバーにページ番号の入力がある。開くときに全ページの寸法を先に集め、正しい高さで並べてから描く
  （100 ページの PDF で 20ms 前後。pdf-lib で作った文字だけの PDF をヘッドレス Chromium で測った）。
- 前回の位置: 論文ごとに、端末の localStorage（`paperlens.pos.<保存先>/<論文 ID>`）にだけ保存する。保管庫には書かないので、
  MCP からは見えない。開いたときに 2 ページ目以降なら移り、「先頭に戻る」を出す。取り込んだ直後と、先に移動の指示が来たときは移らない。
- 右サイドバー: 5つのタブ。対訳は 1 文ずつのカード（訳・メモ・訳さない記録・区切りの直し・用語集）。訳・用語・数式は PDF での操作から追加され、記録はテンプレートの入力欄から作る。
  記録タブの最上部に書誌情報の欄（題名・著者・年・掲載先・DOI）と「BibTeX をコピー」がある。題名を変えても本文の `# 見出し` は変えない。
- ステータスバー: 保存の状態、対訳の解析方式と訳の進み具合、マーカーの数、論文の数、保管庫の名前。
- リスト（`⌘/Ctrl + Shift + L`）: 広いモーダル。単語帳（各論文の用語と、対訳の用語集）と数式帳を、全論文から集める。項目を選ぶと、その論文の該当ページへ移る。
- グラフ: 論文と用語のつながり。同じ用語を調べた論文は近くに配置される。
- 設定とヘルプはモーダルで開く。設定は Obsidian の設定画面と同じ、左に項目・右に中身の形。
- サイドバーの開閉と幅、開いている論文は `.paperlens/workspace.json` に保存する（Obsidian の `.obsidian/workspace.json` と同じ考え方）。

## 保管庫のファイル構成

```
<保管庫>/
  .paperlens/workspace.json     画面の配置
  _templates/reading-note.md    テンプレート（利用者が編集できる）
  papers/20261012-attention/
    paper.pdf                   取り込んだ PDF
    note.md                     読解ノート
    paperlens.json              マーカー・用語・数式（位置などの補助データ）
    sentences.json              1 文ずつの対訳（packages/core の PaperDocument）
    sentences.status.json       解析の進み具合
    slides.pdf                  発表スライド（PPTX は取り込むときに PDF へ変換する）
    slides.pptx                 PPTX から取り込んだときの元のファイル
    slides.json                 スライドを囲んだグループと、論文へのリンク
```

### 発表スライドと論文の対応

- 中央を 2 つに分け、左にスライド、右に論文を並べる。間の溝にグループの色の線を引く（SVG を重ねる）。線はスクロールのたびに DOM の位置から測り直す。
- グループの名前は `Markup-ページ.番号`。番号は作ったときに決め、消しても使い直さない（`slides.json` の `used` にページごとの最大の番号を残す）。ノートや会話で使った名前が別の部分を指さないようにするため。
- 保存は注釈と同じく操作で送る。リンクは 1 本ずつの操作（`addLink` / `removeLink` / `updateLink`）にした。配列ごと置き換えると、画面とエージェントが同時に足したリンクの片方が消えるため。
  送られた操作は書く前にすべて検証し、1 つでも正しくなければ何も書かない。
- 画面の側は、保存を 1 つずつ順に送り、保存か取り込みが終わるたびに世代を進める。読み直しの途中で世代が変わったら読み直す（古い内容で自分の変更を消さないため）。
- PPTX の変換は LibreOffice、無ければ macOS の Keynote（AppleScript）。PowerPoint の自動操作は、開いた文書を確実に指せず、利用者が開いている別のプレゼンを閉じるおそれがあるため使わない。
- グループの色は、色覚の型が違っても隣り合う色を見分けやすい 8 色を固定の順で使う。名前の札を必ず添え、色だけで見分けさせない。

データベースは使わない。アプリを使わなくなっても、ノートと PDF はそのまま残る。
Obsidian の保管庫にしているフォルダを選べば、Obsidian からも同じノートを開ける。

## テンプレートと読解ノート

テンプレートは普通の Markdown である。アプリが読み書きする範囲を HTML コメントで囲む。
Obsidian の閲覧画面ではコメントが表示されない。

```markdown
## 1. 概要をつかむ

### 一言でいうと
<!-- field: summary | 一言でいうと | 何をして何が分かったかを1〜2文で書く -->
（記録タブで入力した内容がここに入る）
<!-- /field -->

## マーカーと訳
<!-- list: highlights -->
（アプリが書き出す）
<!-- /list -->
```

- `field` は「ID | 見出し | 入力のヒント」の形。直前の `##` 見出しが、記録タブでのまとまりになる。
- `list` はアプリが書き出す一覧。`highlights`、`terms`、`equations` の3種類がある。
- `{{title}}`、`{{date}}`、`{{pdf}}`、`{{id}}` は論文の取り込み時に置き換わる。
- 読解の段階は frontmatter の `status` に入る。

初期のテンプレートは、読む段階を4つに分けた（概要をつかむ、精読する、検討する、まとめる）。
段階ごとに書く項目を決めておくと、途中で読むのをやめても、どこまで理解したかがノートから分かる。

### 書き込みの規則

1. 書き込む直前にノートを読み直し、`field` と `list` の範囲だけを書き換える。範囲の外側は変更しない。
2. 同じノートへの書き込みは順番に処理する。読み直しと書き込みの間に別の更新が入らない。
3. 別のアプリでノートを書き換えた場合、アプリに戻った時点で読み直す。
4. `field` の中身は、Obsidian で直接書き換えてもアプリに反映される（ノートが正）。
5. `list` の中身は `paperlens.json` から毎回作り直す。一覧を直すときはアプリの右側で編集する。

5 は割り切りである。一覧を Markdown から逆に読み取る処理は、書式の揺れに弱いため見送った。

### frontmatter の扱い

frontmatter は `src/lib/frontmatter.ts` で項目ごとに読み書きする。YAML のライブラリは使わない。

- 書くのは、対象の項目の行だけである。ほかの項目・コメント・空行・frontmatter の外は 1 文字も変えない。
- 一覧は元の書き方を保つ。ブロック形式（`authors:` の下に `  - A`）はブロック形式で、フロー形式（`tags: [a, b]`）はフロー形式で書き戻す。
  新しく書く一覧と、空の一覧（`[]`）に書く一覧はブロック形式にする（Obsidian の Properties が書く形）。`authors` は一覧で書く。
- 複数行の値（`|`、`>`）、入れ子の対応表、アンカーの項目は書き換えない。画面では欄を読み取り専用にし、API は 409 を返す。
- 項目名に日本語・スペース・引用符を使える（`読了日: …`、`my rating: 4`）。字下げの無い、`- ` と `#` で始まらない行で、
  `:` の後が空白か行末なら項目の始まりとみなす。前の項目の続きとして吸い込まない。
- `true`・`null` などの語と、記号で始まる値は引用符で囲む。数字だけの値（年）は囲まない（Dataview で比べられるように）。

### 書き出す Markdown の形

- マーカー: Obsidian のコールアウト（`> [!quote] p.3（黄）`）。ブロック ID（`^h-...`）を付けるので、他のノートから参照できる。
- 用語: `### [[用語]]` の形。Obsidian のグラフビューでも論文と用語がつながる。
- 数式: `$$ ... $$`。Obsidian と GitHub の両方で表示できる。

## Claude の使い方

| 操作 | 送る内容 | 返す内容 |
| --- | --- | --- |
| 訳す | 選択した文、前後約600字、論文の題名 | 訳文 |
| 用語を調べる | 用語、前後約600字、題名 | 見出し語、読み、定義、説明、この論文での使われ方、関連語 |
| 数式にする | 抽出した文字列、選択範囲の画像、前後の本文 | TeX、記号の説明 |

全文の対訳はこの表に入らない。対訳は Claude が MCP 経由で入れ、画面からは Claude API を呼ばない（読む・直す・区切りを整えることに集中する）。

- 応答は JSON スキーマを指定した構造化出力で受け取る。
- 数式は PDF から抽出した文字列だと記号が崩れるため、選択範囲を切り出した画像も送る。
- API キーはブラウザの localStorage に保存し、保管庫には書かない。保管庫を同期や Git で共有してもキーは含まれない。
- キーが無くても、訳・用語・数式はすべて手で入力できる。
- 日本語の書き方は yomiyasu の方針に合わせ、システムプロンプトで指定した（である調、1文40字前後、比喩を使わない、定訳に英語を添える）。

## デザイン

Material Design 3（M3）のカラーシステムを使った。値は @material/material-color-utilities で計算した。

- 色: ソースカラー #434DA2（今までの主色と同じ色相）、方式 Tonal Spot。明暗の値は CSS の light-dark() で書き、
  data-theme 属性で color-scheme を切り替える。vite.config.ts の cssTarget は、light-dark() をビルド後も残すための設定である。
- PDF のページ: 暗い表示でも白のままにし、ページの中は明るい表示の値を使う（color-scheme: light）。
- マーカー: 不透明の色を、マーカーの層ごと multiply で紙に重ねる。黒い文字は黒のまま残る。
  黄・桃・緑は色名と見た目を合わせるため元の色相、水色だけ主色にハーモナイズした。黄・水色は T90、桃・緑は T78 で、
  色覚の型が違っても見分けやすくした。ページを暗くする表示を足すときは、重ね方を screen に変えて値を計算し直す。
- フォーカス: DADS の黄と黒の2重線をやめ、M3 の輪（secondary の 3px、2px 空ける）にした。輪が出るすべての面で、
  隣の色との比が 3:1 以上あることを計算で確かめた。背景を管理できない PDF のページの中だけ、輪の内側に白い縁を足す。
- 形: ボタンとタグは丸、カード 12px、設定の区画 16px、ダイアログ 28px、入力欄 4px。
- 文字: Noto Sans JP の 400 と 700。本文 16px、行間 1.7。

e2e（`e2e/smoke.mjs` の「暗い表示」）で、4 色のマーカーの中の文字が黒のまま残り、紙の部分がマーカーの値になること、
暗い表示でもページの中の primary が明るい表示の値になること、ページの上のマーカーの点のフォーカスの輪と白い縁を確かめている。

## 画面の文言

yomiyasu（AI が書いた日本語の不自然さを直す指針）を参考に、次の規則で書いた。

- 機能の説明は「〜できます」、利用者への依頼は「〜してください」と書き分ける。
- 比喩を使わない。「保存しています」「保存できませんでした」のように状態をそのまま書く。
- 前置きや締めの言葉を書かない。絵文字を使わない。
- ボタンは動作を書く（「PDF を追加」「訳す」「保存する」）。
